Music Generation — ACE-Step

Generate music on its own — for building a library of beds, restyling an existing track, or producing a sung stinger. Generated files can be saved into a show template from the Promo tab.

Read live from your ACE-Step server. Pick a specific checkpoint (e.g. a fast/turbo model vs. a higher-quality one), or leave on the server default.

Comma-separated style tags work best — instrument, mood, era, production style.

Leave empty and ACE-Step is told [inst] plus a vocal-suppressing negative prompt, which is the reliable way to guarantee no singing. Type lyrics here and both are dropped so the vocal actually comes through — use structure tags like [verse] and [chorus] on their own lines.

What to steer away from. Leaving this empty on an instrumental take still applies a built-in vocal-suppressing default — type anything here (even just re-typing that same idea in your own words) to replace it entirely with your own.

Reference strength: 0.50

Generates in the shape of an existing track — useful for matching a show's established sting, or restyling a bed you already have. Higher strength stays closer to the reference; lower gives the prompt more freedom. Around 0.5 is a good starting point for a style transfer.

ACE-Step reads the reference from a file path rather than an upload, so this needs ACE-Step running on this machine — or ACE_STEP_REF_DIR pointed at a mount both machines resolve identically.

Duration (s): (blank = let ACE-Step pick) BPM: Key: Time signature: Samples: Steps: Seed:

BPM, key, and time signature are all passed as prompt tags (ACE-Step conditions tempo/key/meter on the prompt text for this server rather than taking separate fields for them) — leaving any on auto lets the model pick what suits the style. More samples generate alternatives in one pass — slower, but you audition them side by side. Higher steps means better quality and proportionally more GPU time. Reuse a seed to reproduce a take.

Runs an extra planning pass over your prompt and lyrics before generating, auto-filling in whatever you left on auto (tempo, key, structure). Slower — often better when you don't have strong opinions on the specifics above; leave it off for a fast, literal take on exactly what you typed.

Advanced generation settings Server defaults ▸

The actual quality/style controls ACE-Step's own pipeline exposes underneath the fields above. Left on "server default" (unchanged from before this existed) unless you set them. If your self-hosted output sounds different from a hosted service running the same checkpoint, this is usually why — a tuned service has picked deliberate values here.

Guidance scale: Omega scale (APG):

Guidance scale: how strictly the output follows your prompt/lyrics — ACE-Step's own default is 15; lower gives the model more creative freedom, higher can sound overcooked. Omega scale only matters when CFG type below is "apg" (default 10) — controls how fine-grained that guidance is.

Scheduler: CFG type:

ERG (Enhanced Realism Generation) settings — left unchecked here means "use the server's own default" for each, not "off". Check a box to explicitly force it on; ACE-Step's own pipeline defaults all three to on.

Note: a turbo/distilled checkpoint ignores CFG guidance by design — if your ACE-Step server is running a turbo variant, guidance scale/CFG type/omega scale above may have no audible effect regardless of value.

Set a prompt and duration, then hit Generate. Longer or multi-sample runs take proportionally longer — ACE-Step is polled for up to three minutes.

Text to SFX — Woosh

Generate a one-shot sound effect from a plain description — for building a library of stingers and hits, or auditioning options before picking one for a show template. This is separate from the genre-based SFX the promo generator uses automatically at scene cuts.

Be concrete: name the object and the action, not a mood. Woosh is a sound-effects model, not a music model — style words like "epic" or "cinematic" do less here than a literal description of the sound itself.

Samples:

No duration control -- Woosh has no such parameter itself, so this returns whatever length it naturally generates for the description rather than an artificially trimmed clip. More samples generate that many independent takes of the same description, so you can audition and pick the best one — each is a separate request to Woosh, run one after another.

Describe a sound and hit Generate.

Workflow

What happens, in order, from upload to finished export:

Amber dashed = optional, feeds into the main pipeline rather than sitting inline with it.

  1. Scene detection — PySceneDetect (Content or Adaptive) finds every cut, using the same settings as Scene Detection & Analysis.
  2. Rating — sharpness/brightness/duration/faces (OpenCV), AI Vision quality, and dialogue boosts from faster-whisper.
  3. Beat/dialogue prep (optional) — beat grid and word-level timestamps when those options are on.
  4. Scene selection — highest-rated scenes fill the target duration with spacing, beat/word snaps, and top-up passes.
  5. Assembly — scenes plus title/end cards with the genre transition (or custom matte).
  6. Audio normalize — SOT loudness baseline for later mix steps.
  7. SFX at cuts — Woosh from the genre prompt; procedural fallback only mid-job if Woosh fails.
  8. Background music — ACE-Step or upload, normalized and ducked under SOT.
  9. Narration (optional) — Fish Audio or uploaded VO, normalized before mix.
  10. Final mix — sidechain ducking, gap-aware BGM dips, optional dual-mono, loudness pass.
  11. Export — MP4, ProRes, or AVC-Intra-style packages.

Jobs use a concurrency-limited queue (default 2) so local model servers are not overloaded. Position in queue is shown while waiting.

The Player streams directly when the browser can decode the file. Broadcast masters (ProRes, DNxHD, many MXF) may fail in-browser; the Player then calls POST /api/media/playable to transcode to H.264/AAC MP4 and caches the result. Conversion applies to library picks, not local-only files.

Music & VO tips

ACE-Step lyrics

  • Thinking mode is off; vocal-suppressing negatives are dropped when lyrics are present.
  • Aim for ~2–3 words/sec (about 60–90 words for 30s). Keep lines short (4–8 words).
  • Use [verse] / [chorus] / [bridge] structure tags.

Fish Audio delivery tags

S2 uses square brackets ([happy]); older S1 uses parentheses. Place emotion at the start of a sentence; stack at most two tags.

[confident] Tonight, the story everyone is talking about.
This is [emphasis] the one you cannot miss.
